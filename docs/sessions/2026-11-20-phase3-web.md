# P3-04 browser client

The web build packages the same Rust presenter, editor, package manager and seat-scoped session used on the desktop. The checked-in HTML starts the release WebAssembly on a WebGPU canvas. Games and scenario drafts use separate origin-local save slots. ADR-0021 records the browser host and storage choices.

The PR workflow builds the static bundle, runs Chrome against a localhost server and archives the site and test evidence. The locked wasm32 client check passed. For the Windows browser run, `cargo xtask web-build` generated a 9,817,562-byte WebAssembly module and 106,982 bytes of bindings with wasm-bindgen 0.2.130.

The Rust preview server served the three extracted files from the 2,698,986-byte delivery ZIP over localhost. On Windows with headless Chrome 157.0.8103.79 using D3D11, the release rendered a 1,182 × 648 canvas through WebGPU. A mouse click ended the human turn and let the opponent finish the round. The Game menu wrote a 1,648-character base64 save to origin-local storage. Reloading the page started at turn 0. Opening the slot restored turn 1. The game reported errors for empty and malformed slots and preserved the live game. The scenario editor then saved a turn-2 snapshot in its own slot and preserved the game save byte for byte. After reloading the page a second time, opening the scenario and starting a playtest restored turn 2. The screenshot contained 216 distinct colors sampled on an eight-pixel grid.

The browser package test removed the bundled Woodland package, selected the external manifest and WebAssembly through the file picker, enabled the imported package and applied it to the scenario. The saved 108-tile draft changed by one byte. Tile 1 gained a forest on its open plains. The browser reported one editor command. The receipt identifies the exact module, manifest, plugin and both saves. [Package verification](2026-11-20-phase3-web-package.json)
